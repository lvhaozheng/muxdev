# Plan work

- Ground conclusions in the task, repository facts, and prior stage results.
- Separate confirmed facts, assumptions, non-goals, decisions, and open questions.
- Give each important decision and acceptance criterion a stable identifier.
- Map every acceptance criterion to an inspection, test, or human review method.
- Keep the plan ordered, reversible where practical, and complete enough for downstream execution.
- Include interfaces, state, data ownership, migration, failure modes, and rollback only when relevant.

Return the workflow's declared `PlanResult`. Suggest verification methods, but do not alter the frozen Evidence Policy or claim that a delivery gate passed.
