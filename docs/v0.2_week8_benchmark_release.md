# muxdev v0.2 Week 8: Trusted Benchmark And Release Candidate

## Status

**当前已实现:** Blackboard v7 persists Benchmark executions, hash-chained
events, case results and immutable reports. `trusted-routing-v1` expands to an
executable v2 contract with 24 cases, content-addressed fixture/evaluator
identities and a 48-result Codex/Qwen matrix.

The Replay track executes the coordinator, counterfactual strategies,
gate-first metrics, deterministic 10,000-sample bootstrap and safe result ZIP
without calling a Provider. It is always labelled simulation and cannot create
production routing outcomes or quality claims.

The live track is CLI-only, requires `--yes` plus a positive budget, runs with
Provider concurrency one and pauses before the next Attempt when usage is
missing or budget is insufficient. HTTP has no live entry point.

## Strategy And Metric Boundary

Fixed Codex, fixed Qwen, frozen legacy rules and the v0.2 Router reuse the same
Provider/Case result matrix. Provider external effects are not repeated merely
to score a different route. A high-risk route with no eligible Reviewer is a
safe refusal; forcing an ineligible Provider is a capability mismatch.

Quality weights are functional checks 60%, static checks 15%, blind review 15%
and signed Evidence 10%. Safety violations, capability mismatch, invalid
Attestation or high blockers force quality to zero. Reports expose task
completion separately so safe refusal cannot hide low delivery coverage.

The RC gate needs all 24 strategy results, at least 20 complete real signed
deliveries, zero high-risk mismatch and Router point-estimate regret no greater
than 15%. Confidence intervals are published but Replay never satisfies the
gate.

## Local Authentication

Production Daemon mode requires a daemon-private 256-bit bearer token. CLI and
TUI read it from the private data directory. Browsers exchange a 60-second,
single-use bootstrap nonce for an HttpOnly SameSite=Strict session cookie.
WebSocket validates authentication and loopback Origin before `accept`.

Only the minimal health response and authorization landing page are public.
Non-loopback Daemon binding is refused. Same-user compromise remains a
documented residual risk.

## Release Candidate

The version is centrally defined as `0.2.0rc1`. The release script builds wheel
and sdist twice under a fixed `SOURCE_DATE_EPOCH`, checks byte equality, runs
Twine validation and writes a CycloneDX SBOM, dependency-license projection,
SHA-256 list and `muxdev.release-manifest.v1`.

The manifest explicitly records `benchmark.status=pending_live_gate` until a
real report passes. Nothing in the release workflow publishes to PyPI, creates
a Git tag or uploads Provider credentials.

The PR fast suite remains serial and excludes integration/release cases. The
core suite assigns whole test files to two isolated pytest processes and
enforces a six-minute wall-clock limit; release-only browser, Benchmark,
performance, archive and packaging checks remain a separate Linux job.

```text
muxdev benchmark run trusted-routing-v1 --mode replay
muxdev benchmark run trusted-routing-v1 --mode live --yes --max-cost-usd N
muxdev benchmark report EXECUTION_ID --output results.zip
muxdev auth status
muxdev doctor --production
python scripts/build_release_candidate.py
```
