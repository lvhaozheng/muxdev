# muxdev v0.2 Week 7: Task-First Product And Trusted Demo

## Status

**当前已实现:** muxdev exposes one no-build Dashboard backed by the versioned
`muxdev.task-story.v1` read model. It explains the selected main Agent,
exclusions, durable execution, heterogeneous review, isolation, Evidence and
DeliveryAttestation without exposing raw Provider output or scheduler secrets.

The registered `trusted-delivery-v1` scenario supports a hash-verified,
side-effect-free Replay and a managed Mock/Replay live path. Both are visibly
labelled simulation.

**v0.2 目标:** Week 8 executes the deterministic benchmark track, provides an
explicit cost-bearing live track, hardens local authentication and builds the
`0.2.0rc1` release candidate. No measured Provider-quality claim exists until
that live gate passes.

## TaskStory Contract

TaskStory is a read model, not another source of truth. It projects State,
Execution, Harness, Approval, Review, Evidence and Attestation facts into six
stable phases: submitted, routed, executing, reviewing, verifying and
attested. Every state has a concrete next action.

The timeline returns at most 200 entries and uses an HMAC-bound cursor scoped
to the Run. Task lists return at most 100 entries. Responses omit lease and
fencing tokens, prompts, transcripts, raw Provider streams, private keys,
environment variables and absolute sensitive paths.

## Dashboard

The Dashboard uses embedded HTML/CSS/JavaScript and no remote assets. Its main
path is task list -> current action -> route explanation -> timeline -> review
-> trust -> deliverables. Configuration and historical experimental features
are not the primary navigation.

`task_story_invalidated@1` is emitted only after a persisted event commits.
The browser refreshes the selected TaskStory, reconnects WebSocket with bounded
backoff and uses 15-second polling only as a fallback. Draft text is captured
before refresh.

## Demo Boundary

Replay reads the packaged `muxdev.demo-scenario.v1` projection only. It performs
no shell, network, Provider, database or production-learning write. Live Demo
uses the normal Durable Runtime with managed simulation adapters and produces
a simulation-labelled DeliveryAttestation.

```text
muxdev demo --scenario trusted-delivery-v1 --mode replay
muxdev demo --scenario trusted-delivery-v1 --mode live
```

The four-minute sequence shows route eligibility, independent read-only review,
safe checkpoint recovery, opaque reconciliation and offline tamper detection.

## Interfaces

```text
GET  /api/dashboard/tasks
GET  /api/tasks/{run_id}/story
GET  /api/demo/scenarios
GET  /api/demo/scenarios/{scenario_id}
POST /api/demo/scenarios/{scenario_id}/run
```

The POST accepts a registered scenario only and cannot select a paid Provider,
arbitrary prompt, fault code or Fixture path.
