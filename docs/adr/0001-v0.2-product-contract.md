# ADR 0001: v0.2 Product And Agent-Team Contract

- Status: Accepted
- Date: 2026-07-18

## Context

The v0.1 repository exposes many workflows, roles, providers, governance
surfaces, and experimental automation features. The breadth makes the product
hard to explain and hides the reliability boundary of provider CLI wrappers.
The v0.2 goal is a resume-worthy AI infrastructure project that is also useful
on real local repositories.

## Decision

muxdev v0.2 is a local-first trusted delivery and routing control plane for
coding-agent harnesses.

- The orchestration unit is a task with one isolated workspace and one main
  agent attempt at a time.
- A deterministic harness owns state, routing, policy, recovery, approvals, and
  evidence. Agents own reasoning and tool use within declared boundaries.
- A high-risk task may receive one heterogeneous, read-only, blind reviewer.
- Fixed planner/coder/tester/reviewer chat pipelines are not the default team
  model.
- Routing is quality- and risk-first. Cost and latency break ties rather than
  overriding a quality or safety constraint.
- Codex and Qwen are the first real adapter certification targets; mock and
  replay provide deterministic validation.
- The first production boundary is one operator on one machine. Queue, lease,
  artifact, and identity ports must permit a later self-hosted team deployment,
  but v0.2 does not promise multi-tenancy or remote workers.
- Unsupported capabilities and opaque CLI limitations must be visible in the
  API, UI, evidence, and documentation.

## Consequences

Positive consequences:

- the product has one defensible value proposition rather than a feature list;
- task state and delivery evidence remain provider-neutral;
- multi-agent cost is paid only when risk justifies independent review;
- future team deployment has explicit replaceable boundaries.

Costs and exclusions:

- existing profile/topology configuration is deprecated for new tasks;
- workflow, plugin, LangGraph, semantic-merge, parallel, and learning claims
  that do not own a verified main path move out of the stable surface;
- generic CLI breadth is no longer presented as equivalent to managed adapter
  depth;
- production team identity and distributed scheduling are deferred.

## Validation

The decision is validated by the `trusted-routing-bench`, adapter certification
tests, state-boundary failure injection, signed-evidence verification, and a
task-first product demonstration described in the v0.2 plan.
